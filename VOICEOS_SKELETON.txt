1. DESCRIPCIÓN GENERAL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Plataforma SaaS de call-center con agentes de voz IA (VoiceOS).
  Stack: Next.js 15 + React 19 (frontend/API), Node.js TypeScript (worker de voz),
         Supabase PostgreSQL + pgvector (base de datos + RAG),
         LiveKit (WebRTC/SIP), Groq LLM, Deepgram STT, Cartesia TTS.

  Dos procesos en producción:
    1. Next.js app  → Vercel  (NEXT_PUBLIC_SUPABASE_URL, STRIPE_SECRET_KEY, etc.)
    2. Voice worker → Render  (LIVEKIT_*, DEEPGRAM_API_KEY, CARTESIA_API_KEY, GROQ_API_KEY)

  URL producción: https://nextjs-commerce-jet-five-49.vercel.app

  CRM ANALYSIS — extractCrmAnalysis() (líneas 370-450)
  ──────────────────────────────────────────────────────
  Interface CrmAnalysisData {
    Age, Name, Motivation, interested (bool), occupation, Financial_goal,
    Call_transferred (bool), monthly_expenses, time_in_occupation,
    'In Voicemail' (bool), 'Call Success' (bool)
  }
  - Llama a Groq (llama-4-scout-17b) con el transcript de la llamada
  - Extrae campos CRM como JSON estructurado
  - Limit: transcript.slice(0, 4000) para evitar exceder token limit
  - En error o transcript vacío: retorna objeto "blank" con valores null
  - Se usa al final de cada llamada en el handler Close

  [12] SILENCE REPROMPT + AUTO-HANGUP (líneas 1115-1130)
       _armSilenceTimer():
         setTimeout(4500) → say('¿Hola? ¿Sigues ahí?')
           setTimeout(3500) → say('Parece que hay problemas de audio. Hasta luego.')
                               .then(_doDeleteRoom)
       NOTA DE RIESGO: 4.5s es agresivo para llamadas largas.
       Recomendado para >10min: aumentar a 12_000 / 8_000.

  [13] EVENT HANDLERS (líneas 1132-1413)
       ctx.room.on('disconnected') → ROOM_DELETED o SERVER_SHUTDOWN → say goodbye
       BackchannelManager (3200ms onset, 8000ms max) → Pilar 5
       Tracing spans: sttSpan, llmSpan, ttsSpan (latencia por etapa)

       REGEX FILTERS:
         NEGATIVE_INTENT_RE → "no me interesa", "deja de llamar", "fuck off", etc.
           → Fast hangup: interrupt + say('Entendido, adiós.') + deleteRoom
         VOICEMAIL_RE → "deja tu mensaje", "leave a message", "after the tone", etc.
           → Solo primeros 30s: _voicemailDetected=true + deleteRoom inmediato

       UserInputTranscribed:
         - Partial: barge-in si agentState='speaking' && !lockout && len>=4 && !filler
           → interrupt({force:true}) + _wasInterrupted=true
           → Reduce endpointing a {minDelay:400, maxDelay:1500} por 1 turno
         - Final: filtrar <3 chars o filler-only → _armSilenceTimer()
         - Final válido: endSpan(sttSpan) + startSpan(llmSpan)

       SpeechCreated: endSpan(llmSpan) + startSpan(ttsSpan)

       AgentStateChanged:
         'thinking' → clearWatchdogs + arm thinkingWatchdog (22s)
           Si dispara: say('Disculpa, un momento.')
         'speaking' → clearWatchdogs + arm speakingWatchdog (15s)
           Si dispara: interrupt({force:true}) SILENCIOSO
             Si en 3s sigue en 'speaking': deleteRoom
           También: _speakLockoutUntil = now+450, clearSilenceTimers
         'listening' ← desde 'speaking' → clearWatchdogs + armSilenceTimer

  [14] BALANCE CHECKER PERIÓDICO (líneas 1357-1395)

10. PIPELINE DE VOZ — FLUJO COMPLETO DE UNA LLAMADA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  OUTBOUND:
    1. Frontend → POST /api/calls/dial
    2. API → acquire_call_slot() (Supabase RPC) → rechaza si límite
    3. API → LiveKit CreateRoom + CreateSipParticipant
    4. LiveKit → SIP trunk → número destino (Twilio/Telnyx)
    5. Worker recibe Room → defineAgent.entry() ejecuta
    6. Worker parsea room.metadata: {systemPrompt, voiceId, language, CRM fields...}
    7. Worker → await runStartupCleanup() (ya completado al arrancar)
    8. Worker inicializa: STT (Deepgram nova-2, es, endpointing=300)
                         LLM (Groq llama-4-scout vía openai-compatible)
                         TTS (Cartesia sonic-multilingual, es, chunkTimeout=8s)
    9. session.say(firstMessage) → Cartesia genera audio → LiveKit → SIP → teléfono
   10. Usuario habla → SIP → LiveKit → Deepgram STT → transcript
   11. Transcript → LLM → respuesta → Cartesia TTS → LiveKit → SIP → teléfono
   12. Fin: LLM llama end_call tool → deleteRoom → Close handler
   13. Close handler: upsert calls table + extractCrmAnalysis + release_call_slot
                    + outbound webhook (si configurado)

  INBOUND:
    1. Llamada llega al número Twilio
    2. Twilio → POST /api/webhooks/twilio/incoming
    3. API responde con TwiML que conecta al SIP trunk de LiveKit
    4. LiveKit → Worker → mismo flujo desde paso 5

11. BUGS CORREGIDOS (historial de fixes en esta sesión)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ✅ B-01 CARTESIA HANG / "PARECE" SILENCE
         Causa: ws.close() esperaba 30s en TCP muerto (ws closeTimeout default)
         Fix:   chunkTimeout: 8_000 + Speaking watchdog 15s (recovery silenciosa)
         Archivo: agent/worker_core.ts

  ✅ B-02 HARD CRASH EN RENDER POST-FIRST-CHUNK
         Causa: setKeepAlive() llamado ANTES de connect → error sin listener → crash
         Fix:   Aplicar keepAlive en evento 'connect' + process.on('uncaughtException')
         Archivo: agent/worker_core.ts

  ✅ B-03 STT SORDO EN ESPAÑOL (language='en' hardcodeado)
         Causa: language hardcodeado como 'en' en constructor STT
         Fix:   agentLanguage='es' default, override desde room metadata
         Archivo: agent/worker_core.ts

  ✅ B-04 ENDPOINTING AGRESIVO (25ms default)
         Causa: corta palabras en conexiones móviles
         Fix:   endpointing: 300 (300ms de silencio para considerar fin de turno)
         Archivo: agent/worker_core.ts

  ✅ B-05 LLAMADAS ZOMBIE (slots bloqueados tras crash)
         Causa: worker crash → calls quedan en 'in_progress' → concurrent limit error
         Fix:   runStartupCleanup() al arrancar (cruza con LiveKit.listRooms())
         Archivo: agent/startup-cleanup.ts

  ✅ B-06 BUILD CJS PARA RENDER
         Causa: ESM bundle no compatible con runtime Render
         Fix:   esbuild --format=cjs --target=node24 → dist/worker.js
         Archivo: package.json (build:worker script)

  ✅ B-07 qac/interactions min_score/max_score columna inexistente
         Causa: .gte('overall_score') en tabla qac_interactions (no existe ahí)
         Fix:   .gte('qac_evaluations.overall_score') (relación embebida PostgREST)
         Archivo: app/api/qac/interactions/route.ts:61-62

  ✅ B-08 leaderboard fallo silencioso res.ok===false
         Causa: sin throw en !res.ok → catch nunca ejecuta → usuario no ve error
         Fix:   if (!res.ok) throw new Error('Failed to load leaderboard data')
         Archivo: app/(app)/qa-center/leaderboard/page.tsx:262-271

  ✅ B-09 dashboard errores solo en console.error
         Causa: sin toast ni estado de error visible al usuario
         Fix:   toast.error('Error loading dashboard data') + estado de error UI
         Archivo: app/(app)/dashboard/page.tsx:53-54

      y luego Groq responde superponiéndose. Confuso para el usuario.
      Fix rec: Solo interrupt() silencioso (como el speaking watchdog)
