MÓDULO 1 — AUDIT LOG

    Params: ?page, ?limit, ?action, ?entity_type, ?user_id, ?from, ?to
    Retorna: { data: AuditLog[], total, page }

────────────────────────────────────────────────────────────────────────────────
MÓDULO 2 — AGENT PROFILES
────────────────────────────────────────────────────────────────────────────────

Schema: Sin cambios (tabla qac_agent_profiles ya existe).

APIs nuevas:
  GET    /api/qac/agents
    → Lista de agentes con stats: avg_score, call_count, last_call_at

  POST   /api/qac/agents
    → Crear nuevo perfil de agente

  GET    /api/qac/agents/[id]
    → Detalle del agente + historial de llamadas + métricas + coaching asociado

  PATCH  /api/qac/agents/[id]
    → Actualizar perfil (nombre, email, team, role, hire_date, is_active)

  DELETE /api/qac/agents/[id]
    → Desactivar agente (soft delete: is_active = false)

UI nueva:
  /qa-center/agents
    - Lista de agentes: nombre, equipo, score promedio, llamadas evaluadas, último contacto
    - Botón crear agente
    - Toggle activo/inactivo

  /qa-center/agents/[id]
    - Header: nombre, equipo, score promedio, badge activo/inactivo
    - Historial de llamadas evaluadas (tabla con link a call review)
    - Score histórico (gráfico de tendencia)
    - Coaching asociado (lista de coaching reports)
    - Formulario de edición inline


────────────────────────────────────────────────────────────────────────────────
MÓDULO 3 — COACHING REPORTS
────────────────────────────────────────────────────────────────────────────────

Schema: Sin cambios (tabla qac_coaching_reports ya existe).

APIs nuevas:
  GET /api/qac/coaching
    Params: ?agent_id, ?from, ?to, ?min_priority
    Retorna: { data: CoachingReport[], total }

  GET /api/qac/coaching/[id]
    Retorna: CoachingReport + interaction completa + datos del agente

UI nueva: /qa-center/coaching
  - Lista de reportes de coaching por agente (filtrable por agente, fecha, prioridad)
  - Card por reporte: agente, priority_score, top 2 debilidades, fecha
  - Vista detalle expandible
  - Exportación PDF por agente


────────────────────────────────────────────────────────────────────────────────
MÓDULO 4 — CALL REVIEW (workflow supervisor)
────────────────────────────────────────────────────────────────────────────────

Schema — 2 cambios mínimos:

  1. En tabla qac_interactions — nuevo campo:
     ALTER TABLE qac_interactions
       ADD COLUMN review_status TEXT DEFAULT 'pending_review'
       CHECK (review_status IN (
         'pending_review',
         'in_review',
         'reviewed',
         'approved',
         'disputed'
       ));

  2. Nueva tabla qac_review_comments:
     CREATE TABLE qac_review_comments (
       id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       workspace_id    UUID NOT NULL REFERENCES workspaces(id),
       interaction_id  UUID NOT NULL REFERENCES qac_interactions(id),
       user_id         UUID REFERENCES auth.users(id),
       comment         TEXT NOT NULL,
       created_at      TIMESTAMPTZ DEFAULT NOW()
     );

APIs nuevas:
  PATCH /api/qac/interactions/[id]/review
    Body: { review_status, reviewer_notes? }

  GET   /api/qac/interactions/[id]/comments
    Retorna: lista de comentarios con user info

  POST  /api/qac/interactions/[id]/comments
    Body: { comment }

UI — en /qa-center/calls/[id] existente (sin romper lo actual):
  - Badge de estado en cabecera (Pendiente / En revisión / Revisado / Aprobado / Disputado)
  - Dropdown para cambiar estado (solo admins/managers)
  - Panel de comentarios QA con historial y timestamp
  - Botón "Exportar revisión" (PDF)
