# VoiceOS — Autonomous decisions log

## Providers (Task 5)

### ElevenLabs — REMOVED (active), legacy DB values KEPT

- Deleted dead `lib/elevenlabs/client.ts` (no importers) and
  `app/api/webhooks/elevenlabs/route.ts` (ElevenLabs is not a call provider;
  TTS runs through Cartesia via the worker's TTS router).
- Removed the ElevenLabs entry from `/api/health` and the "ElevenLabs" marketing
  copy in `voice-studio`.
- **Kept (documented, not dropped):** `voice_engine_internal` enum tiers
  (`elevenlabs_v2` / `elevenlabs_v3`) shown in `app/admin/infrastructure/page.tsx`
  and the `agents.elevenlabs_agent_id` / `knowledge.elevenlabs_kb_id` columns.
  These are **DB-enum-mapped values / legacy columns**; renaming them requires a
  data migration (map each `elevenlabs_*` engine tier + any stored voice*id to a
  Cartesia equivalent and preserve `legacy_voice_id`). Deferred to a dedicated
  data migration to avoid corrupting existing rows — same "deprecate, don't drop"
  posture used for the `retell*\*`columns. No`elevenlabs` npm dep existed.

### Resend — KEPT for transactional email

Per the pre-decided policy: transactional/critical emails (verification,
invitations, payment-failed receipts) stay on Resend — it works and migrating
auth emails blind is risk. `lib/email.ts`, `lib/observability/alert-delivery.ts`,
and `app/api/billing/enterprise-inquiry/route.ts` are unchanged. A
`VOICEOS_EMAIL_ENABLED` flag for non-critical email can gate future additions.

### Upstash — KEPT (correct usage)

`lib/ratelimit.ts` is the API rate limiter wired into `middleware.ts` for
`/api/v1/*` Bearer-key traffic — the correct use for a SaaS public API. Kept as-is
(a `REDIS_URL`/ioredis migration is a separate infra task, not dead-code removal).

### dist/ — git-ignored

`dist/worker.js` + `dist/worker.mjs` (build artifacts, regenerated by
`build:worker`) removed from the tree and added to `.gitignore`.
